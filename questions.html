1
Eliminate left recursion from the following grammar.
S → Aa / b A → Ac / Sd / ∈
Left Recursion
▼
📝

This is the standard indirect left-recursion question. A is not obviously left recursive — but A → Sd and S → Aa together give A ⇒ Sd ⇒ Aad, so A ⇒+ Aα.

Order the non-terminals S, A. S has no left recursion, so it is left alone. For A we first substitute S (because S comes earlier in the order), which turns the indirect recursion into a direct one, and only then apply the α/β rule.

3
Find First and Follow Set from following grammar. Check grammar is LL(1) or not?
S → AaAb | BbBa A → € B → €
FIRST & FOLLOWLL(1) Table
▼
📝

A famous exam grammar. Both A and B derive only ε, so FIRST(A) = FIRST(B) = { ε } — which looks like a clash but is not, because the deciding token comes from what follows them.

FIRST(AaAb) = { a } and FIRST(BbBa) = { b } are disjoint, so S can always choose. A and B each have a single production, so their rows cannot conflict either. The grammar is LL(1).

💡
This grammar is the textbook example of a language that is LL(1) but not SLR(1) — worth remembering as a one-line exam bonus.
4
Apply rule to remove left recursion from following grammar.
S → A A → Ad | Ae | aB | aC B → bBC | f C → g
Left Recursion
▼
📝

Straight direct left recursion on A, with two recursive alternatives and two non-recursive ones. Split them:

α₁ = dα₂ = e β₁ = aBβ₂ = aC

Then apply A → βA′ and A′ → αA′ | ε. B and C are untouched — B → bBC starts with a terminal, so it is not left recursive.

5
Define Operator precedence grammar. Convert following production rules of grammar into suitable Operator precedence grammar.
E → EAE | id A → - | *
Operator Precedence
▼
📝

Definition first. An operator grammar has (1) no ε-production and (2) no two adjacent non-terminals on any right-hand side. An operator precedence grammar is an operator grammar in which at most one of ⋖, ≐, ⋗ holds between any pair of terminals.

E → E A E breaks condition 2 twice over. Since every production of A is a single terminal, substitute A back in and the adjacency disappears.

6
Explain Left recursion in brief and remove left recursion from the following grammar.
S → A A → aB / Ad B → bBC / f C → g
Left Recursion
▼
📝

Brief explanation to write in the exam: a grammar is left recursive when a non-terminal A can derive a string beginning with A itself (A ⇒+ Aα). A top-down recursive-descent parser for such a rule calls itself without consuming input and loops forever, so left recursion must be removed before predictive parsing.

Here only A is affected: α = d and β = aB, giving one new non-terminal A′.

S → aAC | Bb A → eD B → f | g C → h | i D → bE | ε E → eD | dD
LL(1) Table03 marks
▼
📝

Six non-terminals, one of them nullable. The only subtlety is D: because D → ε, the production D → ε is entered under every terminal in FOLLOW(D) = { h, i } — not under FIRST.

Every cell ends up with at most one production, so the grammar is LL(1).

10
What is ambiguity in grammar? Eliminate left recursion from the following grammar.
A → Aa | b
AmbiguityLeft Recursion
▼
📝

Ambiguity — definition to write: a context-free grammar is ambiguous if there is at least one string in its language having two or more distinct parse trees (equivalently, two distinct leftmost derivations). Because the parse tree determines meaning, an ambiguous grammar leaves the compiler with no single interpretation — e.g. E → E + E | E * E | id parses id + id * id in two different ways. Ambiguity of an arbitrary CFG is undecidable in general; in practice we rewrite the grammar or supply precedence and associativity rules.

The elimination part is the simplest possible case: α = a, β = b.

11
Construct LL(1) parsing table for following grammar.
S → iCtSeS | iCtS | a C → b
LL(1) TableAmbiguity
▼
📝

The dangling-else grammar (i = if, C = condition, t = then, e = else). Two alternatives of S share the prefix iCtS, so M[S, i] receives both — the grammar is not LL(1).

Left factoring gives S → a | iCtSS′ and S′ → eS | ε. But e is in FIRST(eS) and in FOLLOW(S′), so M[S′, e] still holds two entries.

⚠
The point of the question: this grammar is genuinely ambiguous — "which if does this else belong to?" — and no amount of factoring removes ambiguity. Real compilers resolve it by a rule: an else matches the nearest unmatched if.
